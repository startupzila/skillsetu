## Goal

Build CMS-managed static pages (about, contact, privacy, terms, refund, affiliate-disclosure) and a custom code manager (controlled head/body scripts — analytics, verification tags, ad scripts — role-restricted + audit-logged).

## What Was Built

### Database: Static Pages Tables
Added two new tables to the Prisma schema and applied to Supabase:
- **`static_pages`** — slug, status, sort_order, show_in_footer, published_at
- **`static_page_translations`** — per-language title, content, meta_description, status

RLS: public read published pages; writes service-role only. Triggers: updated_at.

### Static Pages Service (`src/lib/content/pages-service.ts`)
- `getPublishedPageBySlug(slug, language)` — read a published page
- `listFooterPages(language)` — list pages that show in footer
- Admin: `adminListPages`, `adminGetPage`, `adminCreatePage`, `adminUpdatePageTranslation`, `adminPublishPage`

### Public Static Page Route (`/[slug]`)
- Catch-all route for CMS pages (about, privacy, terms, etc.)
- `generateMetadata` for SEO (title, description from page)
- Breadcrumbs (Home > Page title)
- Article layout with title + content
- `notFound()` for non-existent slugs

### Dynamic Footer
- Footer now fetches CMS-managed pages from `listFooterPages()`
- Splits into "Company" (about, contact) and "Legal" (privacy, terms, refund, affiliate-disclosure)
- Footer links update automatically when pages are published/unpublished

### Custom Code Manager

**Custom code service** (in `pages-service.ts`):
- `getActiveCustomCode()` — read active code entries (for injection)
- `adminListCustomCode`, `adminCreateCustomCode`, `adminUpdateCustomCode`, `adminDeleteCustomCode`
- All require `settings.manage` permission + audit logging

**API routes:**
- `GET/POST /api/admin/custom-code` — list + create
- `PATCH/DELETE /api/admin/custom-code/[id]` — update (toggle active) + delete

**Custom code injection** (`src/components/seo/custom-code-injector.tsx`):
- Server component: fetches active code for a given location
- Renders raw HTML via `dangerouslySetInnerHTML`
- Injected into `layout.tsx` at `body_start` and `body_end`

**Console page** (`/console/custom-code`):
- Create form: name, location selector (head, body_start, body_end), code textarea
- List of code entries: name, location badge, active/inactive badge, code preview, toggle, delete
- Toggle active/inactive with toast feedback

### Console Pages
- **`/console/pages`** — pages table (title, status, slug, footer visibility, edit/publish actions)
- **`/console/pages/new`** — create page form (title, auto-slug, content textarea, meta description)
- **`/console/pages/[id]`** — page editor (edit title, content, meta; save; publish)

### Seeded Data
6 static pages (all published, EN translations):
- about, privacy, terms, contact, refund, affiliate-disclosure

2 custom code entries (both inactive):
- Google Analytics (head)
- Schema Verification (head)

## Key Decisions

1. **Static pages are CMS-managed** — content editors can create/edit/publish without code changes.
2. **Footer is dynamic** — fetches published pages from DB, splits into Company/Legal based on slug.
3. **Custom code uses `dangerouslySetInnerHTML`** — only authorized roles (settings.manage) can create/activate code entries; audit logged.
4. **Code injection is server-side** — `CustomCodeInjector` is a server component, so code is in the initial HTML (not client-injected).
5. **Head injection** — currently handled via body_start/body_end in layout; head injection will use Next.js metadata API or a custom head component in production.
6. **Static page route is `[slug]`** — placed at the end of the (public) route group so it doesn't shadow /skills, /courses, /search, etc.
