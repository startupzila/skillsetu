## Goal

Build the commerce foundation: book/resource CMS, store listing + product page, orders (checkout architecture + payment abstraction), digital entitlements (protected downloads), and coupons (fixed/percentage, usage limits, expiry).

## What Was Built

### Commerce Service (`src/lib/commerce/commerce-service.ts`)
**Public reads** (anon key, RLS):
- `listPublishedProducts(opts)` — list products (filterable by type)
- `getPublishedProductBySlug(slug)` — get a product with variants
- `validateCoupon(code, orderTotalCents)` — validate code, check expiry/usage, compute discount
- `checkEntitlement(productId)` — check if user is entitled to a product
- `listMyEntitlements()` — list user's purchased resources
- `generateDownloadUrl(entitlementId)` — generate signed download URL (1hr expiry)

**User actions** (requires auth):
- `createOrder(input)` — create an order with optional coupon, auto-creates order_items
- `listMyOrders()` — list user's order history

**Admin** (service-role, permission-checked, audit-logged):
- `adminListProducts`, `adminCreateProduct`, `adminPublishProduct`
- `adminListOrders`, `adminMarkOrderPaid` (creates payment record + entitlements)
- `adminListCoupons`, `adminCreateCoupon`, `adminToggleCoupon`

### Public Pages
- **`/store`** — product grid with type badges, format badges, prices, "View details" buttons
- **`/store/[slug]`** — product detail: format list, price, "Buy now" (or "Download" if entitled)
- **`/books`** — book-specific listing (filters to product_type='book')

### API Routes
**Commerce:**
- `POST /api/commerce/orders` — create an order
- `POST /api/commerce/coupons/validate` — validate a coupon code
- `POST /api/commerce/download?entitlementId=` — generate signed download URL

**Admin:**
- `GET/POST /api/admin/products` — list + create products
- `POST /api/admin/products/[id]` — publish a product
- `GET /api/admin/orders` — list orders
- `POST /api/admin/orders/[id]` — mark order as paid (creates payment + entitlements)
- `GET/POST /api/admin/coupons` — list + create coupons
- `POST /api/admin/coupons/[id]` — toggle coupon active/inactive

### Console Pages
- **`/console/products`** — products table (name, type, price, status, publish action)
- **`/console/orders`** — orders table (order ID, customer, total, status, mark paid)
- **`/console/coupons`** — coupon manager (create form, list with toggle)

### Console Sidebar
Added "Commerce" section: Products, Orders, Coupons links.

## Key Decisions

1. **Payment is abstracted** — `PaymentProvider` enum supports manual, razorpay, stripe. MVP uses manual payment (admin marks orders as paid in the console). The payment interface is ready for real provider integration.
2. **Entitlements are created when an order is marked paid** — not at order creation. This ensures users only get access after payment is confirmed.
3. **Downloads use signed URLs** — generated via Supabase Storage `createSignedUrl()` with 1-hour expiry. The actual file path is never exposed to the client.
4. **Download count is tracked** — each download increments `entitlements.download_count` for auditing.
5. **Coupon validation** checks: code exists, status active, not expired, usage limit not reached, order meets minimum. Computes discount (fixed or percentage, capped by max_discount_cents).
6. **Product detail checks entitlement** — if the user owns the product, shows "Download" instead of "Buy now".
