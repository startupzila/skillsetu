## Goal

Build the SEO system: per-entity SEO metadata, dynamic XML sitemap, robots.txt, JSON-LD structured data (Website, Breadcrumbs, Course), and a redirect manager (301/302 with audit).

## What Was Built

### SEO Service (`src/lib/seo/seo-service.ts`)
- `getSeoMetadata(entityType, entityId, language)` — read per-entity SEO metadata (public read via anon key)
- `matchRedirect(pathname)` — check if a path matches an active redirect
- Admin functions (service-role):
  - `adminListRedirects()` — list all redirects
  - `adminCreateRedirect(input)` — create a redirect (audit-logged)
  - `adminDeleteRedirect(id)` — delete a redirect
  - `adminToggleRedirect(id)` — toggle active/inactive
  - `adminListSeoMetadata()` — list SEO metadata entries
  - `adminUpsertSeoMetadata(input)` — create or update SEO metadata

### Dynamic XML Sitemap (`src/app/sitemap.ts`)
- Static pages (/, /skills, /courses, /search, /about, /login, /register)
- All published categories (/skills/[slug])
- All published courses (/courses/[slug])
- All published lessons (/courses/[course]/[module]/[lesson])
- Only published content included (RLS enforced)
- 18 URLs generated from current seed data

### Robots.txt (`src/app/robots.ts`)
- Allows all crawlers on `/`
- Disallows `/console/`, `/api/`, `/dashboard`
- References the sitemap URL
- Host directive set to site URL
- Removed conflicting static `public/robots.txt`

### Redirect Manager (middleware integration)
- Updated `src/middleware.ts` to check redirects on every request
- Queries the `redirects` table for matching `from_path` + `is_active = true`
- Returns 301 or 302 redirect before any other processing
- Skips API routes and static assets

### JSON-LD Structured Data (`src/components/seo/json-ld.tsx`)
- **`JsonLdWebsite`** — schema.org/WebSite with SearchAction (on homepage)
- **`JsonLdCourse`** — schema.org/Course with provider, educationalLevel, CourseInstance (on course pages)
- **`JsonLdBreadcrumbs`** — schema.org/BreadcrumbList (on course pages)
- All render `<script type="application/ld+json">` tags

### Console Pages
- **`/console/redirects`** — redirect manager:
  - Create form (from_path, to_url, status code 301/302, notes)
  - Table of redirects with status badges, active/inactive toggle, delete
  - Client-side `RedirectsManager` component

### Console Sidebar

### API Routes
- `GET/POST /api/admin/redirects` — list + create redirects
- `POST/DELETE /api/admin/redirects/[id]` — toggle + delete

## Key Decisions

1. **Sitemap is dynamic** — generated from DB on each request, only published content included.
2. **Redirects checked in middleware** — before session refresh or auth checks, so redirects work even for unauthenticated users.
3. **JSON-LD is server-rendered** — `dangerouslySetInnerHTML` with JSON.stringify, no client-side hydration needed.
4. **robots.txt uses the Next.js route** (`robots.ts`) — not a static file, so it can reference the dynamic site URL.
5. **SEO metadata is per-entity + per-language** — stored in `seo_metadata` table, keyed by (entity_type, entity_id, language_code).
6. **Redirect status codes**: 301 (permanent) or 302 (temporary), configurable per redirect.
