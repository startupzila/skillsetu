## Goal

Build learner authentication (register/login/logout/email verification/password reset via Supabase Auth), `/console` protection middleware, server authorization helpers, audit logging, and the console dashboard.

## What Was Built

### Auth Library (`src/lib/auth/`)
- `permissions.ts` — 19 permission constants + 11 role constants
- `session.ts`:
  - `getSession()` — fetches user + profile + roles + permissions from DB
  - `requireUser()` — throws `AuthError(UNAUTHENTICATED)`
  - `requireRole(...roles)` — throws `AuthError(FORBIDDEN)`
  - `requirePermission(perm)` — throws `AuthError(FORBIDDEN)`
  - `hasPermission(session, perm)` / `hasRole(session, ...roles)` — boolean checks
  - `isStaff(session)` — is the user a console-capable role?
  - `AuthError` class with `code: 'UNAUTHENTICATED' | 'FORBIDDEN'`
  - super_admin implicitly has `'*'` permission (all permissions)
- `audit.ts` — `recordAudit()` writes immutable audit logs via service-role admin client
- `index.ts` — barrel export

### Middleware (`src/middleware.ts`)
- Refreshes Supabase session on every request
- Protects `/console/*` → redirects to `/login?redirect=...`
- Redirects logged-in users away from `/login` and `/register` to `/dashboard`

### Auth API Routes (`/api/auth/`)
| Route | Purpose |
|---|---|
| `POST /register` | signUp with email verification (validates password ≥ 8 chars) |
| `POST /login` | signInWithPassword |
| `POST /logout` | signOut |
| `POST /forgot-password` | resetPasswordForEmail (anti-enumeration — always returns success) |
| `POST /reset-password` | updateUser password |
| `GET /callback` | exchangeCodeForSession for email verification redirects |

### Auth UI Pages (`src/app/(auth)/`)
- `layout.tsx` — shared card-based layout with SkillSetu branding
- `/login` — email + password form, loading + error states, redirect param support
- `/register` — display name + email + password, success screen after registration
- `/forgot-password` — email form, success state (anti-enumeration)
- `/reset-password` — new password + confirm, validation
- `/verify-email` — notice page for email verification

### Console (`src/app/console/`)
- `layout.tsx` — protected layout requiring auth + `isStaff()`
  - Shows "no access" for authenticated non-staff (not a redirect loop)
  - Sidebar nav + header with user info + sign out
- `page.tsx` — dashboard showing:
  - User account (email, verified status, user ID)
  - Roles (badges)
  - Module access cards (permission-gated)
  - Permissions (full list or "All permissions (super_admin)")

### Other
- `/unauthorized` (403) page
- Homepage updated with auth-aware header (Sign in/up vs Dashboard/Console/Sign out)
- `docs/security.md` — auth model, RBAC layers, RLS, audit logging, MFA readiness, secret management, security checklist

## Three-Layer Authorization (Defense in Depth)

1. **Server helpers** — `requirePermission()` throws `AuthError(FORBIDDEN)`
2. **Supabase RLS** — enforces row-level access at DB level
3. **Middleware** — redirects unauthenticated users from `/console`
