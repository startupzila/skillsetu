## Goal

Build the learning system: lesson completion + course progress (server-authoritative), bookmarks (toggle + saved), notes (CRUD, private), chapter quizzes (interactive UI + scoring + attempt history).

## What Was Built

### API Routes

| Route | Method | Purpose |
|---|---|---|
| `/api/bookmarks` | GET | List current user's bookmarks (optional type filter) |
| `/api/bookmarks` | POST | Toggle a bookmark (add/remove) |
| `/api/notes` | GET | List current user's notes (optional lesson filter) |
| `/api/notes` | POST | Create a private note |
| `/api/notes/[id]` | PATCH | Update a note (owner only) |
| `/api/notes/[id]` | DELETE | Delete a note (owner only) |
| `/api/quiz/attempts` | POST | Start a quiz attempt (creates in_progress row) |
| `/api/quiz/attempts` | PUT | Submit + grade an attempt (computes score, marks completed) |

All routes require authentication (return 401 if not signed in). RLS enforces self-only access to learner data.

## Key Decisions

1. **Server-authoritative progress**: `requireUserId()` extracts `auth.uid()` from session — client-provided `user_id` is never trusted. RLS enforces self-only access.
2. **Quiz scoring is server-side**: the client sends selected options; the server fetches correct answers from DB, grades, computes score, and stores the attempt.
3. **Correct answers revealed only after submission**: `QuizRunner` shows correct/incorrect + explanations in the results phase, never during answering.
4. **Notes are private by default**: `is_private = true` enforced in the service layer + RLS.
5. **Bookmark toggle is idempotent**: clicking Save when already saved removes the bookmark.
6. **Quiz attempt lifecycle**: in_progress → completed. Score, correct_count, total_questions stored in the attempts table.
