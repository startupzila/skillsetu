## Goal

Build the media library (upload to Supabase Storage, browse, metadata, alt text, usage tracking), video metadata model support, and a feature-flagged video block in the content renderer.

## What Was Built

### Supabase Storage Buckets
Created two buckets via the Supabase Storage API:
- **`media`** (public) — images (course thumbnails, lesson images, author photos)
- **`downloads`** (private) — paid digital resources (PDFs, eBooks)

### Admin Media Service (`src/lib/admin/media-service.ts`)
- `adminListMedia(opts)` — list assets (paginated, filterable by file_type)
- `adminGetMedia(mediaId)` — get a single asset
- `adminCreateMedia(input)` — create a DB record (after upload)
- `adminUpdateMedia(mediaId, updates)` — update alt_text, caption, source, license
- `adminDeleteMedia(mediaId)` — delete DB record + Storage file
- `adminUploadMedia(file, opts)` — upload to Storage + create DB record (all-in-one)
- `getMediaUrl(bucket, path)` — generate public URL for an asset

### API Routes
- `GET /api/admin/media?type=image&limit=50` — list media
- `POST /api/admin/media/upload` — upload file (multipart/form-data, validates type + size)
- `PATCH /api/admin/media/[id]` — update metadata
- `DELETE /api/admin/media/[id]` — delete asset + Storage file

File upload validation:
- Allowed types: JPEG, PNG, WebP, GIF, SVG, PDF
- Max size: 10MB
- Unique storage path (timestamp + random + sanitized filename)

### Media Library Console Page (`/console/media`)
- **Server component** fetches media via admin service, builds public URLs for images
- **Client component** (`MediaLibrary`) with:
  - **Upload button** (file picker, multiple files, drag-to-upload style)
  - **Grid** of media cards: image preview (or file icon for PDFs), filename, type badge, file size, Edit + Delete buttons
  - **Edit dialog**: alt text input, caption textarea, live preview
  - **Delete** with confirmation
  - Toast feedback for all actions
  - Empty state ("No media yet. Upload files to get started.")

### Video Block Enhancement
Updated `VideoBlock` in the ContentRenderer to support real video metadata:
- **Provider-aware embeds**: YouTube (`youtube.com/embed/ID`), Vimeo (`player.vimeo.com/video/ID`)
- **Thumbnail fallback**: shows image if no embed available
- **Duration display**
- **Placeholder fallback**: when no provider/videoId set, shows "Video metadata set, but no provider/video ID configured"

### Console Sidebar
Added "Media" link in the console sidebar under Content.

## Key Decisions

1. **Storage buckets**: `media` is public (images need public URLs for SEO + performance); `downloads` is private (paid resources need entitlement checks).
2. **Upload validates type + size** server-side — never trust client-provided file metadata.
3. **Unique storage paths**: `timestamp-random-slugified-filename` prevents collisions.
4. **Delete cleans up both** Storage file + DB record (if Storage delete fails, DB record still deleted — logged but not blocking).
5. **Video block supports embeds** (YouTube/Vimeo) — no custom video streaming in MVP, but the architecture supports it. Future: self-hosted video with provider='self-hosted'.
6. **Media library is client-side** after initial SSR fetch — uploads, edits, deletes update the grid without full page reload.
