## Goal

1. Redesign the lesson page to a w3schools-style layout: fixed left sidebar with all chapters, Previous/Next at top AND bottom, mobile/tablet collapsible chapter menu.
2. Build the console: layout, courses list, course editor, lesson editor with basic CRUD.

## What Was Built

### w3schools-style Lesson Layout

**New components:**
- **`CourseSidebar`** (`src/components/learning/course-sidebar.tsx`) — w3schools-style left sidebar showing all modules + lessons. Current module expanded by default, others collapsible. Current lesson highlighted.
- **`PrevNextNav`** (`src/components/learning/prev-next-nav.tsx`) — 3-column prev/next nav (Previous | Current Title | Next). Used at BOTH top and bottom of lesson. Cross-module navigation (flattens all lessons to find adjacent).
- **`MobileCourseNav`** (`src/components/learning/mobile-course-nav.tsx`) — hamburger "Chapters" button that opens CourseSidebar in a left Sheet. Visible on mobile/tablet (`lg:hidden`).

**Updated lesson page** (`/courses/[slug]/[module]/[lesson]`):
- Desktop (`lg+`): fixed left sidebar (256px, sticky, full height) with all chapters
- Mobile/tablet (`<lg`): "Chapters" button → Sheet with sidebar
- Prev/Next at TOP (with current lesson title in center)
- Prev/Next at BOTTOM (with "Course" link in center)
- Cross-module navigation: flattens all lessons across modules to find prev/next

### Console CRUD

**Admin service** (`src/lib/admin/content-service.ts`):
- `adminListCourses()` — list all courses including drafts (requires `course.read`)
- `adminGetCourse(id)` — get a course by ID including drafts (requires `course.read`)
- `adminCreateCourse(input)` — create course + EN translation (requires `course.create`)
- `adminUpdateCourse(id, updates)` — update course fields (requires `course.update`)
- `adminPublishCourse(id)` — publish course (requires `course.publish`)
- `adminArchiveCourse(id)` — archive course (requires `course.publish`)
- `adminListModules(courseId)` — list modules + lessons for a course
- `adminCreateModule(input)` — create module + EN translation
- `adminCreateLesson(input)` — create lesson + EN translation (requires `lesson.create`)
- `adminPublishLesson(id)` — publish lesson (requires `lesson.publish`)
- `adminUpdateLessonTranslation(id, updates)` — update title/summary

All operations use the service-role admin client (bypasses RLS), require authentication + permission checks, and record audit logs.

**Admin API routes:**
- `GET/POST /api/admin/courses` — list + create courses
- `PATCH/POST /api/admin/courses/[id]` — update + publish/archive
- `GET/POST /api/admin/lessons` — get + create + publish + update-translation

**Console pages:**
- **`/console/courses`** — courses list with table (title, status, difficulty, duration, actions: edit/view/publish/archive). "New Course" button.
- **`/console/courses/new`** — create course form (title, slug auto-generated, difficulty, duration, descriptions, learning outcomes). Creates course + redirects to editor.
- **`/console/courses/[id]`** — course editor: course info card + curriculum (modules + lessons with status badges, edit links). Publish button for drafts.
- **`/console/courses/[id]/lessons/[lessonId]`** — lesson editor: edit title/summary, save, publish. Content-block editor placeholder (full in S10).

## Key Decisions

1. **w3schools-style sidebar is fixed on desktop** — `sticky top-16 h-[calc(100vh-4rem)]` so it stays visible while scrolling.
2. **Cross-module prev/next** — flattens all lessons across modules so "Next" at the end of one module goes to the first lesson of the next module.
3. **Mobile sidebar is a Sheet** — opens from the left, full height, with a close button. Same CourseSidebar component.
4. **Console uses admin service** — service-role admin client (bypasses RLS) so drafts are visible. Permission checks enforced via `requirePermission()`.
5. **Audit logging** — every create/publish/archive/update records an audit entry.
6. **Soft delete (archive)** — courses are archived, not hard-deleted, preserving published URL history.
