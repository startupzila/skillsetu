## Goal

Define the Prisma schema for Identity, Taxonomy, Content, and Blocks/Media. Generate SQL DDL, RLS policies, triggers, and seed data. Create service modules and API routes to read published content.

## What Was Built

|---|---|
| **Identity** | `profiles`, `roles`, `permissions`, `user_roles`, `role_permissions` |

| **Content** | `courses`, `course_translations`, `course_categories`, `course_authors`, `modules`, `module_translations`, `lessons`, `lesson_translations` |

## Key Design Decisions

1. **Translation entities** (never `title_en`/`title_hi` columns)
2. **Lesson blocks belong to `lesson_translations`** — each language version has its own blocks
3. **`block_type` is a String** (extensible), validated by Zod in service layer
4. **UUIDs with DB-level `gen_random_uuid()`** — works with Supabase JS client
5. **`updated_at` via DB trigger** — since we use the Supabase JS client, not Prisma Client
6. **Scoped slug uniqueness** — modules per course, lessons per module
